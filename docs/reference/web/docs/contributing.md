# Contributing

## Required context

Read these files before changing the application shell, information architecture, interaction model, or visual system:

1. `PRODUCT.md`
2. `DESIGN.md`
3. `docs/SHAPE-BRIEF.md`
4. `docs/CONTRACT.md`

Run `npm run check` after changing any of them. Context validation emits machine-readable diagnostic codes and rejects missing sections, placeholder markers, unresolved image-probe state, unapproved briefs, and omitted core journeys.

## Design constraints

- Optimize the default path for exception supervision.
- Keep production structure and media inspection primary; agent conversation is contextual.
- Use a persistent structure region, focused production canvas, and contextual inspector as the desktop starting point.
- Preserve immutable attempts and make revision, provenance, cost, staleness, and rerun consequences visible.
- Provide complete keyboard and focus behavior from the first component.
- Implement both operating-system themes together.
- Do not introduce card-grid dashboards, decorative AI styling, glassmorphism, gradient text, colored side-stripe accents, or ornamental motion.

## Contract constraints

Browser state is a projection. Mutations use generated gateway contracts and revision checks. The browser must not access arbitrary filesystem paths, store provider credentials, own Pi processes, silently select providers, or hide material downgrades behind fallback content.

## Seed design lifecycle

`DESIGN.md` is currently a pre-implementation seed. Once the scaffold contains real tokens and components, rerun the design documentation process in scan mode. Replace the seed with extracted normative tokens and generate the `.impeccable/design.json` sidecar without changing the approved product principles or shape silently.
